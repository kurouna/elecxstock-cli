# elecxstock-cli の設計

elecxstock が手元に貯めたデータを、ターミナルで `top` のように表示し続ける CUI。状態: **v0.1.0 で実装済み**。

- 画面は 5 つ（`1` マーケット・`2` スクリーナー・`3` ウォッチリスト・`4` 保有・`5` ポートフォリオ）。銘柄のチャートは
  どの画面からも `Enter` で入る**詳細**にする（番号のタブにしない）。
- **読むだけ**。取得（Yahoo・JPX への通信）と利用者のデータの書き込みはアプリに任せる。**elecxstock のコードは 1 行も変えない**（§9）。
- 画面の例は `docs/screenshots/`（`npm run shots`。架空のデータ `.fixture/data` を Windows Terminal で動かして撮る）。

参照した elecxstock の文書: `docs/requirements.md`（§0 判断 5・§1.2・§3・§4・§6.15〜6.17・§7.2 FR-C12・§8）、`design-market-board.md`、
`design-breadth.md`、`design-portfolio.md`、`CLAUDE.md`。レビュー（2026-11-16、Opus 5.5・Fable 5.2 のサブエージェント）の指摘を反映済み。

---

## 1. 目的と範囲

- **目的**: アプリを開かなくても、ターミナルの片隅で「市場・監視銘柄・保有・予定」を横目で見続けられるようにする。
- **やること（v1）**: 手元のデータ（市場データの DB と利用者のデータ）を読んで表示する。データが変わったときだけ読み直す。
- **やらないこと**:
  - データの取得（アプリの自動の更新と F5 に任せる）。利用者のデータ（★・ウォッチリスト・保有・アラート・スクリーン・設定）の書き込み。
  - リアルタイムの株価（elecxstock 自体が扱わない）。表示は「取得したときの値」で、いつの値かを必ず出す。
  - ローソク足（ターミナルの文字では読みにくい。推移は面のチャートで描く）。

## 2. 全体の形

```
┌ ターミナル ──────────────────────────────────────────┐
│ elecxstock-cli                                        │
│  ├ 画面: market / screener / watch / holdings / folio  │
│  │       ＋ detail（Enter で入る 1 銘柄の詳細）          │
│  ├ model/: 画面のモデルを作る純粋な関数（数・文字を決める）  │
│  ├ view/ : 描画（Ink。幅と高さに合わせて並べるだけ）       │
│  └ source/: 読み口（読み取り専用の DB・利用者のデータ）     │
└──────────────┬────────────────────────────────────────┘
               │ 同じファイルを読む（書くのはアプリだけ）
┌ elecxstock（Electron アプリ）┴─────────────────────────┐
│ Core: 取得・指標の計算・利用者のデータの書き込み              │
└────────────────────────────────────────────────────────┘
```

### 2.1 データの場所

アプリと同じ決め方で探す（elecxstock の `src/main/index.ts` と同じ）。

1. `--data <フォルダ>`（`market.db` と `user\` がある `data` フォルダ。スタブで作った架空のデータを見るときなど）
2. 環境変数 `ELECXSTOCK_USER_DATA` があれば `<それ>\data`（アプリの開発・テストと同じ変数）
3. 無ければ Electron の `userData` と同じ場所の `data`: Windows は `%APPDATA%\elecxstock\data`
   （macOS は `~/Library/Application Support/elecxstock/data`、Linux は `$XDG_CONFIG_HOME/elecxstock/data` か `~/.config/elecxstock/data`）

- 中身: `market.db`（`-wal`・`-shm` が付く）・`user\`（`settings.json`・`watchlists.json`・`screens.json`・`holdings.json`・
  `portfolioHistory.json`・`alerts.json` など）。elecxstock-cli は `market.db` と `user\` だけを読む。
- 見つからなければ、探した場所を並べて「elecxstock を一度起動して初回の取り込みを済ませてください」と出す。
- `elecxstock-cli --where`: 使うフォルダ・DB の版・最終更新・elecxstock-cli が対応する elecxstock の版を出して終わる。

### 2.2 elecxstock のコードの使い方

- elecxstock を **git のサブモジュール**（`vendor/elecxstock`）として持ち、そのソースを import する。使ってよいのは **`src/shared/`** と、
  **開いても書かない `src/core/` の関数**（`Repo` の読むメソッド、`folio.ts` の計算の関数など）だけ。`src/renderer/` は原則使わない
  （ストアや i18n を引き込むため）。例外は `src/renderer/lib/folio.ts`（`@shared` だけを使う純粋な関数。ポートフォリオの数をアプリと同じにするため、
  `rowsOf`・`totalsOf`・`heroNumbers`・`divRows`・`divSummary`・`divYields` を使う）。開くと書く部品（`Db`・`CoreService`・`UserStore`・`FolioBook`・`AlertBook`）も使わない（§9）。
  ただしテスト（架空のデータを作る種と、§8 の突き合わせ）では `CoreService` を使ってよい。
- **版を固定する**: サブモジュールは elecxstock の**タグ（リリースした版）**に合わせる（今は `v0.1.13`）。データを書くのは
  インストールしたアプリなので、作業中のソースとずれると `metrics` の列や JSON の形が合わない。
  - elecxstock-cli の `package.json` の `elecxstock.version` に対応する版を書く。DB の版（`user_version`）は `src/source/db.ts` の
    `DB_VERSION` に持ち、サブモジュールの `Db` が作る版と同じかをテストで確かめる。利用者のデータの版は `STORE_VERSION` をそのまま使う。
  - 版を上げるときは `git -C vendor/elecxstock checkout v<版>`、`package.json` を直し、テスト（とくに突き合わせ）を通す。
- **別名と依存**: elecxstock は `@shared/*`・`@core/*` の別名で import しているので、tsconfig・Vitest・esbuild に同じ別名を置く。
  `zod`・`fflate` は elecxstock-cli の `node_modules` から解決する（elecxstock と同じ版にそろえる）。
- **配布**: Ink・React・elecxstock のモジュールを esbuild で 1 本にまとめる（起動を速くするため）。

### 2.3 実行環境

- **Node 24 LTS 以上**を下限の候補にする。`node:sqlite` は 22.13 / 23.4 でフラグが要らなくなり（まだ実験的）、25.7 で
  Release Candidate になった。`readOnly` の付いた版は Node の文書に書かれていないので、実機で下限を確かめてから決める。
  実験的な機能の警告（`ExperimentalWarning`）が標準エラーに出ると画面が崩れるので、出る版では起動時に抑える。
- Windows Terminal（Cascadia のフォント）を主に確かめる。

## 3. 画面の共通の作り

```
 elecxstock-cli  11/13(金) 18:40  大引け後     データ 11/13 15:30（2時間前）  読み直し 18:24  アラート 2  次の予定 11/26 権利付最終日 8951

  1 マーケット  2 スクリーナー  3 ウォッチリスト  4 保有  5 ポートフォリオ  › 8951 日本ビルファンド投資法人
                               ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
╭─ （画面ごとのカード。端末の高さいっぱいに使う） ───────────────────────────────────────╮
╰───────────────────────────────────────────────────────────────────────────────────╯
  ↑↓ 選ぶ  Enter 詳細  [ ] リスト  v 格子                    / コード  m 金額を隠す  ? キー  q 終了
```

- **状態の行**: 日時（分まで）・市場の状態（場中・大引け後・休場。`src/shared/calendar.ts`）・データの基準（最後の更新とその経過）・
  最後に読み直した時刻・**鳴ったアラートの数**・**次の予定**（権利付最終日・決算・分配金の支払い）。狭いときは後ろから省く。
  数え続ける表示（次の読み直しまでの秒数）は置かない。
- **タブ**: 今の画面だけアクセントの色の地と下線。狭い（110 桁未満）ときは短い名前（市場・スクリーン・ウォッチ・保有・PF）。
  詳細を開いているときは `› コード 銘柄名` を足す。金額を隠しているときは札を出す。
- **中身**: 端末の高さいっぱいに使う。一覧は見える行だけを出し、選んだ行に追従してずらす（`12–40 / 312` を出す）。
  Ink は出力が端末より高いと全体を消して描き直してちらつくので、**全体の高さは端末の行数 − 1 を超えない**（最後の 1 行はあける）。
- **キーの案内**: 最下行に固定。左にその画面のキー、右に共通のキー。

### 3.1 見た目（モダン・スタイリッシュに）

- **色はアプリのトークンから**: elecxstock の `app.css` のダークテーマの色を 24 ビット色で使う（文字 3 段・線・アクセント・`--up` / `--down`・
  `--gold`・`--yield-line`）。**地は塗らない**（端末の地の色のまま）。端末の地が明るいときのために `--theme light` で明るい側の色に切り替える
  （既定は dark。アプリの設定には合わせない）。24 ビット色が出せなければ 256 色に寄せ、`NO_COLOR` なら色を使わない。
- **色の意味を絞る**: 上げ（赤）・下げ（青）・選択（青の地と左の `▌`）・目標利回り（青緑）・配当の金額（金）・注意（黄。「仮」「古い」「アラート」）。
  それ以外は文字の 3 段の明るさで差をつける。
- **カード**: 角の丸い細い枠。見出しは枠の中の 1 行目に小さく、右に補足（件数・並び順・範囲）。
- **数字**: 等幅で右にそろえ、桁区切り。名前を切り詰めるときは次の列との間に 1 桁あける。
- **グラフは行の高さを使わない字で描く**: Windows Terminal はブロックの字（`█▁▏` など）をセルの上下いっぱいに描くので、上下の行の棒が
  つながって塊に見える（レビューで最優先の指摘）。そこで次のように描く。
  - 52 週の位置: 細い線の上の印（`─────●───`）
  - 1 年の推移（一覧）: 点字 1 行（区間の最小〜最大を縦につなぐ）
  - 構成比・騰落・損益寄与: 太い線（`━`）。損益寄与は 0 を中心に左（損）と右（益）、最大値で長さをそろえる
  - 詳細と資産推移: 半ブロック（`▄` `█`）で塗った**面のチャート**（縦は行の 2 倍の細かさ）。線の色は中立（上げ下げで色を変えない）。
    面のチャートはグラフの本体なので、塗りがつながってよい
  - 格子の小さなチャート: 点字の線（区間の最小〜最大を縦につなぐ。高値・安値を間引きで落とさない）
- **目盛り**: 価格はきりのよい値（90,000・100,000）。右の軸に今の株価（`◀ 105,000`）と目標利回りの線（`┤ 5.5% 108,091`）を、
  きりのよい目盛りより優先して出す。日付は左端に始まりの年月、1 年以内は月（1 月は「2026年1月」）、1 年を超えたら年。
- **変化を静かに見せる**: 読み直しで値が変わったセルだけ、上げ・下げの淡い地で 1.5 秒光らせて戻す。動き続ける飾りは使わない。
- **記号**: 幅が曖昧な字（★◆●⟳ など）と絵文字（🔔）は、端末とライブラリで幅の数え方がずれて隣の字に重なる（★が「お」に重なった）。
  使う記号は一覧にして決める: `▌ ● ━ ─ ┄ ┤ ◀ ▔ ├ ┬ ┘` と点字・半ブロック。★◆🔔 は使わず、「お気に入り」「アラート」の文字の札にする。
  幅の数え方は 1 か所の関数で決め、テストで固定する（§8）。
- **金額を隠す**（`m`）: 評価額・損益・数量・配当の金額を `••••••` にする（人目に触れる場所で使うため）。率と株価は隠さない。

### 3.2 キー

画面をまたいで、同じキーは同じ意味にする。

| キー                | 動き                                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `1`〜`5` / `Tab`    | 画面を切り替える（詳細からでも）                                                                                                     |
| `↑↓` `PgUp` `PgDn`  | 行を選ぶ（格子では `← →` も）                                                                                                        |
| `Enter`             | 選んだ銘柄の詳細を開く                                                                                                               |
| `Backspace` / `Esc` | 詳細から戻る（`Esc` は端末で遅れることがあるので `Backspace` を主にする）                                                            |
| `n` `N`             | 詳細で、開いた元の一覧の次・前の銘柄                                                                                                 |
| `/`                 | コードを打って詳細を開く（入力のあいだは数字・英字は入力に回り、画面は切り替わらない。`Enter` 開く・`Backspace` 消す・`Esc` やめる） |
| `[` `]`             | スクリーン・リストを切り替える                                                                                                       |
| `v`                 | 表と格子を切り替える（スクリーナー・ウォッチリスト）                                                                                 |
| `,` `.`             | 期間（3M・6M・1Y・5Y）。詳細・格子・資産推移                                                                                         |
| `t`                 | 時間軸（D・W・M）。詳細                                                                                                              |
| `c`                 | 損益寄与の期間（今日・今月・今年・取得来）。ポートフォリオ                                                                           |
| `s`                 | 並べ替え（列を順に）                                                                                                                 |
| `m`                 | 金額を隠す・出す                                                                                                                     |
| `r`                 | すぐ読み直す                                                                                                                         |
| `?`                 | キーの一覧（何かキーを押すと閉じる）                                                                                                 |
| `q` / `Ctrl+C`      | 終了（端末を元に戻す）                                                                                                               |

- 大文字と小文字だけが違うキーは作らない（CapsLock や IME で取り違えるため）。`Shift+矢印` も使わない（端末で取りこぼしやすい）。
- ターミナルには押した文字が来るので、IME が ON のときの全角（`１`・`ｍ`）も NFKC で半角に直して同じに扱う。

## 4. 画面

### 4.1 マーケット（`1`）

- 左: 指数・為替などの一覧（elecxstock の `MARKET_REFS`）。列は値・前日比・1 か月・年初来・**日付**（米国は前日の値なので、その日の
  東証の日付と違えば黄色）。連動 ETF で代えたものは名前に「連動ETF」（FR-U6）。
- 右: 騰落（プライム・J-REIT の上げ・下げ・新高値・新安値・売買代金と、上げと下げの比率の線。`src/shared/breadth.ts`）、
  値上がり率・値下がり率・売買代金の上位（高さに合わせて件数を決める）。`↑↓` で値上がり率の行を選び `Enter` で詳細。
- 狭い（118 桁未満）ときは上下に並べる。

### 4.2 スクリーナー（`2`）

- アプリで保存したスクリーンを `[` `]` で切り替える。上のカードに条件、下に結果（表か格子）。
- 結果は elecxstock の `screener.run` と同じ関数で `metrics` から作る（アプリと同じ件数・並び）。条件の編集はしない（読むだけ）。

### 4.3 ウォッチリスト（`3`）

- アプリのウォッチリスト（お気に入り・売買候補・利用者が作ったもの）を `[` `]` で切り替える。`v` で表と格子。
- **表の列**（左から。`prio` の大きい列から、幅が足りなければ落とす）: コード・銘柄（「仮」の札）・終値・前日比・利回り・
  4%水準まで（設定の目標利回りのうちいちばん低いものの株価まで、今の株価から何 %）・52 週の位置・権利月・1 年の推移。
  利回りは目標利回り以上なら青緑。
- 銘柄名は残りの幅を使う。選んだ行は銘柄で覚える（読み直しで並びが変わっても動かない。elecxstock の `SelectionFollow` と同じ考え）。
- **格子**: 小さなチャートのカードを幅で 2〜4 列、高さで段数を決めて並べ、選んだ行が入るページを出す。カードは銘柄・終値・前日比・
  期間の騰落率・点字の推移・期間の始まりと終わりの年月・価格の幅。

### 4.4 保有（`4`）

- 口座（NISA 成長・つみたて・旧 NISA・特定・一般）ごとの見出しに小計を、**明細と同じ列の位置**に出す（評価額・今日・含み損益・率・構成比・
  配当/年・取得利回り）。最後に合計（同じ列）。
- 明細の列: コード・銘柄・数量・取得単価・現在値・評価額・今日・含み損益・率・構成比・配当/年（特定・一般は税引後。税率は elecxstock の
  `DIVIDEND_TAX`）・取得利回り。保有の計算は elecxstock と同じ関数を使う。

### 4.5 ポートフォリオ（`5`）

- 上の段: 評価額（現金を除く）と今日・含み損益・トータル損益・最高値から・取得額・口座の構成（線）・日経平均と TOPIX 連動 ETF の今日。
  **配当のカードを同じ大きさで**: 年間の見込み（税引後）・前年比・取得利回り・今の利回り。
- 資産推移: 面のチャート（`,` `.` で期間。高さに合わせて行数を決める）。右の軸に万円のきりのよい目盛り。
- 下の段: 損益寄与（`c` で期間。0 を中心に左右の線）と**今後 30 日の予定**（権利付最終日・決算・分配金の支払い）。
- 配当の分析の段（増減の要因・月ごとの見込み）は v2。

### 4.6 詳細（`Enter`）

- 見出し: コード・銘柄名・区分・権利月、株価・前日比・「仮」か「確定」・基準の日時・お気に入りの札、時間軸（`t`）・期間（`,` `.`）・期間の騰落率、
  目盛りの範囲の外にある目標利回り。
- チャート: 面のチャート（高さいっぱい）。目標利回りの線を点線で（FR-C12 と同じ。`src/shared/yieldLines.ts`）。右の軸に今の株価と目標利回り。
  下に日付の目盛り。
- 指標: 実績利回り・配当（REIT は「分配金」）・PER（REIT は「—」）・PBR・52 週の位置・移動平均からの乖離・直近の配当と連続増配。
- 保有・アラート: 口座ごとの数量・取得単価・含み損益（% と円）。アラートの条件と、鳴ったか・条件までの距離（`src/shared/alerts.ts`）。

## 5. 読み直しと描き直し

- **変わったかの確認**: 2 秒ごとに `PRAGMA data_version`（開いたままの接続で、ほかの接続がコミットしたら値が変わる）と、`user\*.json` の
  更新時刻を見る。どれも変わっていなければ何もしない。データが変わるのはアプリが取得したときだけ（日に数回）。
- **読み直し**: 変わったときだけ、見えている画面の分を読む。`metrics`（1 行に指標がまとまっている）を中心に読むので軽い。
  一覧の 1 年の推移や資産推移は、見えている行の分だけ日足を読み、`data_version` が同じならとっておいた値を使う。
- **読みは短く終える**: 文は `.all()` で読み切り、読みかけの文やトランザクションを残さない。アプリのチェックポイント
  （`wal_checkpoint(TRUNCATE)`）や `VACUUM` を待たせないため。
- **描き直し**: 時計は分までなので、描き直しは分が変わったときと、読み直したとき・キーを押したときだけ。
- **値の新しさ**: 状態の行に「データ 11/13 15:30（2時間前）」。一覧の行にも「仮」の札、基準日が古い行（FR-S13）は薄く。
  場中に取得した値は「途中」。

## 6. アプリと同時に使う

- アプリが動いていても動いていなくても、elecxstock-cli は読むだけ。取得はアプリの自動の更新（FR-F6）と F5 に任せる。
- **アプリが動いているかは v1 では判定しない**（`jobs` 表は異常終了で「実行中」が残るので当てにならない）。代わりに「最後の更新からの経過」を出す。
- v3 で elecxstock-cli から日々の更新を流すなら、アプリと同時に書かない仕組みが要る（elecxstock を変えずにできるか、そのときに決める）。

## 7. 作り（フォルダ）

```
elecxstock-cli/
  src/
    main.ts            入口: 起動・終了（どう終わっても端末を元に戻す）
    args.ts            引数（--data・--where・--tab・--theme・--no-color）
    app.ts             全体: 状態の行・タブ・画面・キーの案内・読み直し
    state.ts           キー操作（純粋な関数 reduce）。選択は行のキーで持つ
    source/            読み口: 場所の決め方・読み取り専用の DB・利用者のデータ・変わったかの確認（Reader）
    model/             画面のモデルを作る関数（行・数・予定）。アプリの renderer/lib/folio.ts の純粋な関数も使う
    view/              描画の部品の計算（文字の幅・小さなグラフ・目盛り・列の選び方・書式）
    ui/                Ink の画面（parts.ts の部品と screens.ts の 5 つの画面・詳細・キーの一覧）
  vendor/elecxstock/   elecxstock のサブモジュール（リリースのタグに固定）
  scripts/             まとめる（build.mjs）・単一実行ファイル（sea.mjs）・架空のデータ（fixture.ts）・スクリーンショット（shots.ps1）
  tests/               e2e（キー操作・端末の大きさ・読み取り専用）・unit（純粋な関数・アプリとの突き合わせ）
  docs/design.md       この文書
```

- きまりは elecxstock に揃える: 計算・変換・判定は描画に書かず `model/`・`view/`・`state.ts` の関数にしてテストする。キーは `state.ts` の `reduce` に足し、`?` の一覧（`ui/screens.ts` の `Help`）と README も直す。画面の文言は日本語だけ（v1）。
  テスト・スクリーンショットのデータはすべて架空（elecxstock のスタブで作った DB を使う）。
- 描画の土台を先に作る: 高さの上限を守る外枠、見える行だけを出す窓、文字の幅の関数、列の優先度で落とす表。

## 8. テスト

- **model の単体テスト**: elecxstock のスタブ（`ELECXSTOCK_PROVIDER=stub`・時刻は `ELECXSTOCK_NOW`）で作った架空の DB と利用者のデータを
  入力にして、画面のモデル（行・数字・印）を確かめる。elecxstock-cli も `ELECXSTOCK_NOW` を受ける（市場の状態・「途中」・予定までの日数のため）。
- **アプリと数字がずれない**: 写した材料（§9）ごとに、同じ DB から elecxstock の `CoreService` が返す値と突き合わせる
  （`CoreService` は開くと書くので、DB をテストごとに一時フォルダへ写してから作る）。
- **読み取り専用**: 読む処理を全部呼んだあと、`market.db` の中身（ハッシュ）と `user\` のファイルが変わっていない（`-shm` は除く）。
  DB の版が違えば止まる。壊れた JSON を読んでも、ファイルは移動されない。
- **同時に動かす**: アプリ（`CoreService`）が書き込み・チェックポイント・`VACUUM`・利用者のデータの保存をしているあいだに elecxstock-cli が読んでも、
  アプリが失敗しない・elecxstock-cli が止まらない。
- **描画**: 80・100・120・150 桁（格子の列数の境目を含む）と、高さ 24・40 行で、文字の並び（色を外したもの）をスナップショットで固定する。
  色は「どのトークンを使ったか」を別に確かめる。文字の幅（曖昧な字・全角・点字）を単体テストで固定する。
- **実際の端末**: 文字の並びのテストでは、ブロックの字がつながる・枠がずれるといった見た目の崩れは拾えない。Windows Terminal での
  スクリーンショットを、リリースの前の手順に入れる。
- **キー**: 仮の入力を流して、画面の切り替え・選択の追従・コードの入力のあいだのキー・詳細の行き来を確かめる。

## 9. 読み取り専用で読む（elecxstock は変えない）

elecxstock の Core は「開いたら書く」作りになっている（`CoreService` は参照の行を書き、`Db` は DB を移行し、`UserStore` は `backups\` を
作って壊れたファイルを移す）。そこで elecxstock-cli は**これらの部品を使わず、自分で読み取り専用で開く**。

| 読むもの               | elecxstock-cli の読み方                                                                                                                                                                                                                                                                                                     |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `market.db`            | `new DatabaseSync(path, { readOnly: true })`（`node:sqlite`）。SQLite が書き込みを拒むので、間違って書く処理を呼んでも DB は変わらない。設定は `busy_timeout` だけ                                                                                                                                                          |
| 表の読み方             | `Repo` の**読むメソッドだけ**。`Repo` は `Db` を受ける（`Db` は private のメンバーを持つクラスなので、読み取り専用の接続を包んだ入れ物を `as unknown as Db` で渡す）。使うメソッドの一覧を elecxstock-cli に持ち、テストで固定する（`Repo` は `run` や `tx` も使うので、一覧の外を呼ばない）                                |
| DB の版                | `PRAGMA user_version` が、ビルドのときに焼き込んだ版（§2.2）と違えば止めて「elecxstock-cli と elecxstock の版をそろえてください」と出す                                                                                                                                                                                     |
| `user\*.json`          | `readFileSync` で読み、`{ version, data }` の `data` を elecxstock の zod のスキーマ（`USER_FILE_SCHEMAS`）で確かめる。設定は `DEFAULT_SETTINGS` と浅く混ぜる（アプリと同じ）。版が焼き込んだ `STORE_VERSION` と違えば止める。読めないときは移動も退避もせず「読めなかった」と出し、次の確認でもう一度読む                  |
| 計算                   | `src/shared/`（騰落・目標利回り・保有・ポートフォリオの数）と `src/core/folio.ts` の計算の関数（`seriesResult`・`contribOf`・`dividendsOf`）をそのまま呼ぶ                                                                                                                                                                  |
| 計算の材料（写すもの） | `CoreService` の中にある材料の組み立ては elecxstock-cli に写す。**写すものの一覧**: `folioMarket`（終値・分割・配当の引き方）・`holdings`（`portfolio.list`）・`data.status`・`screener.run` の入力（★・ウォッチリスト・保有の条件）・`alertViews` の一部。数百行になるので、それぞれに §8 の突き合わせのテストを必ず付ける |

- **試した結果（2026-11-16、Node 25）**: WAL の DB を、書く側が閉じて `-wal`・`-shm` が片付いたあとでも読み取り専用で開けた（そのとき
  `-wal`・`-shm` は作られるが、`market.db` の中身と更新時刻は変わらない）。読み取り専用の接続から書こうとすると拒まれた。書く側が
  開いたまま書いた行は、読み取り専用の接続からすぐ読めた。
- **書き込み可能で開いて書かない、にしない理由**: elecxstock の部品をうっかり使うと開いた時点で書く、elecxstock-cli の不具合で書いても止めるものが無い、
  の 2 つを防げないため。読み取り専用なら SQLite が必ず拒む。
- **前提**: 開くと `-shm` が作られることがあるので、データのフォルダに書けない環境（別のユーザー・同期のフォルダの制限など）では開けない。
  そのときの文言を用意する。アプリは `market.db` を消したり置き換えたりしない前提（elecxstock-cli が開いているあいだは Windows では置き換えられない）。
- **写す量が増え続けるなら**: 材料の組み立てを純粋な関数として elecxstock 側に出すのが本筋。そのときは「elecxstock を変えない」を見直す。

## 10. 決めたこと

| 項目                 | 決めたこと                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------- |
| elecxstock の参照    | サブモジュール（`vendor/elecxstock`）をタグに固定して import。DB の版はテストでそろえる（§2.2）         |
| 描画                 | Ink。文字の幅の関数と、高さの上限を守る外枠を先に作る                                                   |
| 画面                 | 5 つ＋詳細（`Enter`）。チャートは番号のタブにしない                                                     |
| 読み直し             | 2 秒ごとに `data_version` で確かめ、変わったときだけ読む（10 秒ごとの読み直しとカウントダウンはやめた） |
| アプリが動いているか | v1 では判定しない。最後の更新からの経過を出す                                                           |
| コマンド名           | `elecxstock-cli`                                                                                        |
| 配布                 | Node.js の単一実行ファイル（SEA。`node --build-sea`）。`v*` のタグで GitHub Releases に exe を公開する  |
